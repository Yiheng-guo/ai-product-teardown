# 同任务竞品对比

功能清单用于了解范围；产品选择结论必须围绕同一用户任务和可比较的证据。只比较用户指定的产品；用户未指定竞品时可提出候选与理由，不擅自注册账号或付费试用。

## 建立共同基线

先固定目标用户、输入素材、目标输出、验收规则、语言、设备、套餐、模型设置和观察时间。版本或能力不同不必抹平，但要说明差异怎样影响结论。确认材料使用权限；不得为对比擅自向其他厂商上传私有文件。

将各产品证据分为实际观察、官方宣称、未知。同一维度如果一方只有宣传资料而另一方有实测，标为“不可直接比较”。缺失数据记 N/A 或未知，不算零分。找不到功能不等于功能不存在。

## 按任务结果比较

优先选择对决策有用的维度：

- 任务完成：结果满足预先声明的哪些验收项？
- 首次可用结果时间：从提交有效输入开始，到首次满足验收为止；区分等待与用户操作时间。
- 返工：完成前需要几次修改、人工修补或重做？
- 控制与恢复：是否能限定修改范围、回退、保留已认可结果？
- 交付：可编辑性、格式、引用、版本和下游可用性。
- 费用：同一任务的实际账单/积分，与标价分列；不混算不同积分体系。

同一案例只支持这个案例的比较。要评价稳定性，提出重复样本计划；未经授权不执行。不同任务不要合成一个胜负结论。

## 评分和输出

默认给维度证据表与“什么场景选什么”的条件结论，不强制排行榜。用户明确要求评分时，先给维度锚点、权重及来源；未知项排除并同时显示已覆盖权重。覆盖不足或条件不可比时不计算可排序的总分。

使用 [对比模板](../assets/comparison-template.md)。每条“值得借鉴”的建议应连接：竞品观察 → 适用场景 → 本产品适配条件 → 风险 → 验证指标。不要把照搬按钮当成可证明有效的增长策略。
